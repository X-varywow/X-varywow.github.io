

Reverse Engineering

在**没有源代码**的前提下，对二进制程序（exe/dll/so/apk 等）进行分析，搞懂它的**逻辑、算法、协议、数据结构**。



## 基础知识

- 汇编 （如 windows 的 x86）
- c
- 静态分析工具 (不运行程序，直接分析二进制/代码， 常用工具：Ghidra， IDA)
- 动态调试工具 (x64dbg, winDBG)
- 动态插桩与 Hook (在程序运行位置 观察调用和修改行为)


-----------

这里重点了解 .NET/ C# 程序逆向

- dnSpy：神器，可以直接看 C# 源码、**动态断点、修改内存、改代码保存**，分析 Unity C# 游戏首选。
- de4dot：脱壳工具，处理.NET 加密。



## 常用术语


1. **偏移(offset)** ：逆向找到目标数据在内存里的地址偏移；读内存工具就是硬编码这些偏移。游戏版本更新，偏移一变工具直接失效。
2. **Hook** ：拦截程序函数调用，可以改参数、接管逻辑（风险极高，反作弊重点打击）
3. **脱壳** ：程序被加密打包，运行时才解密，必须脱壳才能正常反编译。
4. **结构体还原** ：逆向最重要工作：还原内存里面对象结构，知道哪个位置存血量、坐标、物品 ID。

-----------

DMA direct memory access, 是主板上独立硬件控制器， 直接在 外设-内存之间搬运数据，不需要 CPU 参与数据拷贝；

1. **传统板卡 DMA（FPGA）**：PCIe 硬件，直接访问主机物理内存，就是上面讲的，游戏外挂圈的 DMA。
2. **普通设备 DMA（硬盘、显卡、网卡）**：电脑里本来就大量在用。比如固态硬盘读写、显卡把显存数据输出到显示器，全是靠 DMA 搬运，不占用 CPU。


## 反作弊


### 1.内存

查看内存，修改内存极易被发现；

---------


常用外部内存读取工具流程：

`OpenProcess(PROCESS_VM_READ, false, gamePid)` → 获取游戏进程句柄 → `ReadProcessMemory` 循环读取内存。

游戏客户端注册了对象回调，内核层面可能直接捕获发起进程的 hash, pid 上传至服务器；

类似的调用留痕检测方式：hook `ReadProcessMemory` 底层最终调用的 `NtReadVirtualMemory`
